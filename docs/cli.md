# CLI EUTERPIA — справочник

`euterpia` — первый полноценный интерфейс ядра (линия v0.3). CLI —
**равноправный клиент** Core (§60), а не «второй Core»: он не содержит
бизнес-логики и ходит в ядро только через публичные API (§20, §63).

CLI обязан быть `machine-readable` и `composable` (MANIFEST §19-§21):
человекочитаемый вывод для человека, `--json` для агента и скриптов,
никаких «полуструктурированных» форматов.

- Точка правды о поверхности команд — реестр `cli/registry.nim`.
  `--help` и `help --json` строятся из него, поэтому не расходятся (#96).
- Проверить машинную справку: `euterpia help --json`.
- Исходная задача: [#96](https://github.com/framefrok/Euterpia_core/issues/96).

## Грамматика вызова

```text
euterpia [глобальные ключи] <команда> [аргументы команды]
euterpia [глобальные ключи] <команда> [--] [аргументы]
euterpia help [команда]
euterpia --version
```

- Глобальные ключи распознаются **и до, и после** имени команды
  (`euterpia --json node list` и `euterpia node list --json` — одно и то же).
- `--` прекращает разбор ключей: всё после него команда получает как есть.
- Запуск без аргументов печатает справку и завершается кодом 0 — это
  ответ на вопрос, а не ошибка.

## Режимы вывода

| Режим | Как включить | Куда что идёт |
|---|---|---|
| human (умолчание) | `--human`, настройка `output=human` | результат — строки в **stdout** |
| json | `--json`, настройка `output=json` | ровно **одна строка JSON** в stdout |

Правила (закреплены в `cli/context.nim`):

- **stdout — только результат команды.** Логи Core, предупреждения и
  ошибки идут в **stderr**; иначе `--json` перестал бы быть парсируемым.
- Вывод **детерминирован**: нет времени и случайных значений, повторный
  запуск даёт байт-в-байт тот же результат (критерий приёмки #88).
- Приоритет режима и настроек: **argv > env (`EUTERPIA_*`) > файл
  настроек > умолчание** (#258). Источник значения показывает
  `euterpia config get <ключ>`.

## JSON-конверт

Машинный ответ — версионированный конверт (`schema`), поля нагрузки
лежат **рядом** с ним, а не во вложенном объекте (MANIFEST §21):

```json
{
  "schema": 1,
  "ok": true,
  "command": "version",
  "exitCode": 0,
  "name": "euterpia",
  "version": "0.3.1"
}
```

- `schema` — версия схемы конверта. Меняется только при несовместимом
  изменении полей: клиент обязан заметить, что схема другая.
- `ok` — инвариант `ok == (exitCode == 0)`. Агенту достаточно одного поля.
- `command` — имя команды, к которой относится ответ.
- `exitCode` — тот же код, что вернул процесс (не «результат в JSON»).
- При ошибке добавляется объект `error`:

```json
{
  "schema": 1,
  "ok": false,
  "command": "nonsense",
  "exitCode": 1,
  "error": {
    "kind": "usage",
    "message": "неизвестная команда: nonsense",
    "hint": "список команд: euterpia --help"
  }
}
```

`error.kind` — стабильное значение для агента: `usage` (данные/использование),
`env` (среда), `panic` (баг CLI).

## Коды возврата

| Код | Значение | Пример |
|---|---|---|
| 0 | успех | команда выполнена |
| 1 | ошибка данных или использования | неизвестная команда/ключ, лишний аргумент, значение вне диапазона, провал `project validate` |
| 2 | ошибка среды | нет библиотеки, аудиоустройства или прав; недоступный бэкенд |
| 3 | внутренняя ошибка (баг CLI) | необработанное исключение; просьба приложить `euterpia --version` |

`doctor` возвращает 0, если нет провалов проверок, и 2 — если есть.
`analyze --fail-on <уровень>` возвращает 1 при дефектах не ниже уровня.

## Глобальные ключи

| Ключ | Назначение |
|---|---|
| `--json` | машиночитаемый вывод: ровно одна строка JSON в stdout |
| `--human` | человекочитаемый вывод (перекрывает настройку `output=json`) |
| `--verbose`, `-v` | лог Core уровня DEBUG в stderr |
| `--quiet`, `-q` | только ошибки в stderr |
| `--dry-run` | показать изменения, ничего не записывая на диск |
| `--help`, `-h` | справка; с командой — справка по команде |
| `--version` | версия CLI и ядра |

## Справочник команд

Ниже — поверхность команд релиза. Полная машинная версия — всегда
`euterpia help --json` (и `euterpia help <команда> --json`).

### `init` — создать проект

```text
euterpia init [файл] [ключи]
```

Создаёт `.eut` с метаданными и **пустым** графом. Файл по умолчанию —
`project.eut`; существующий не затирается без `--force`.

- Умолчания: `--tempo 120`, `--sr 48000`, `--ts 4/4`.
- `--name`/`--author` задают метаданные; без `--name` имя берётся из имени файла.
- Ноды добавляет `euterpia node add` (#90).

Ключи: `--name`, `--author`, `--sr`/`--sample-rate`, `--tempo`,
`--ts`/`--time-signature`, `--force`.

### `project` — работа с файлом проекта

```text
euterpia project <show|set|validate> [файл] [аргументы]
```

- `show` — метаданные, граф, треки/клипы, автоматизация, состояния плагинов.
- `set <поле> <значение>` — поля `name`, `author`, `tempo`, `sample-rate`,
  `time-signature`. Пишет атомарно (tmp + rename) и обновляет
  `metadata.modified`.
- `validate` — отчёт о формате и целостности; провал даёт код 1.
- Без файла команды работают с `project.eut`.

### `midi` — экспорт проекта в MIDI

```text
euterpia midi <проект.eut> [--out файл.mid] [--split каталог]
```

- Формат 1: дорожка-дирижёр (имя, темп, размер) + по дорожке на непустой трек.
- `--split` — по файлу на инструмент (формат 0).
- Без `--out` и `--split` рядом пишется `<проект>.mid`.
- Тики проекта и SMF совпадают по разрешению (PPQ), позиции не
  пересчитываются; Note Off обрезается границей клипа, зацикленный клип
  повторяется до конца песни.
- `--dry-run` печатает план и не пишет файлов.

### `node` — ноды графа

```text
euterpia node <list|types|add|rm|show> [аргументы] [--file проект.eut]
```

- Тип ноды — полный id (`euterpia.osc`), короткий (`osc`) или имя (`Oscillator`).
- Порты, задержка и умолчания параметров берутся из описателя типа.
- `id` назначается как максимум + 1; `--id` задаёт явно (занятый id — ошибка).
- `rm` удаляет и связи, автоматизацию и состояния плагинов этой ноды.
- `types` печатает каталог (id, порты, параметры) и текстом, и в `--json`.

### `connect` / `disconnect` — связи

```text
euterpia connect <источник> <приёмник> [--file проект.eut]
euterpia disconnect <источник>[:порт] <приёмник>[:порт] [--file проект.eut]
```

- Порт: `нода:out` | `нода:in` | `нода:audio:1` | `нода:ctrl:0` | `нода:event:0`.
- Виды портов обязаны совпадать; самосоединение разрешено — компиляцию
  проверяет `graph check`.
- `disconnect` без портов снимает все связи между парой нод, с портами —
  только указанную.

### `param` — параметры ноды

```text
euterpia param <list|get|set> [аргументы] [--file проект.eut]
```

- Значение проверяется по диапазону типа: вне диапазона — отказ, а не запись.
- Параметр можно назвать именем (`freq`) или числовым id.
- `get` показывает и значение из файла, и умолчание типа.

> Известный дефект флагов параметров (дробные значения) — issue
> [#292](https://github.com/framefrok/Euterpia_core/issues/292), план v0.3.2.

### `graph` — проверка графа

```text
euterpia graph check [--file проект.eut]
```

- Проверяет структуру (типы, порты, связи, значения параметров) **и**
  компилирует граф через Core — CLI не собирает пайплайн сам (§20).
- Провал — код 1; предупреждения (пустой граф, самосоединение) код не меняют.
- Отчёт — те же секции и `summary`, что у `project validate` и `doctor`.

### `render` — офлайн-рендер в WAV

```text
euterpia render [проект.eut] [выход.wav] [ключи]
```

- Вывод — WAV (PCM 16 или 24 бита, стерео). MP3/OGG требуют кодировщика
  и в ядре отсутствуют.
- Длительность: `--seconds`, иначе конец последней ноты + `--tail`
  (умолчание 2 с). Проект без нотных событий требует `--seconds`.
- Частота и блок: argv > метаданные проекта > настройки > умолчание.
- `--dry-run` печатает план и не пишет файл.

Ключи: `--file`, `--out`, `--seconds`, `--tail`, `--master`,
`--sample-rate`, `--block`, `--bits`.

### `notation` — текстовая нотация

```text
euterpia notation <check|import> <файл.notes> [ключи]
```

- `check` — разбор с указанием «строка:колонка»; ошибка разбора даёт код 1.
- `import` — партитура становится клипом дорожки; дорожка и клип
  создаются при необходимости. Повторный импорт той же партитуры даёт
  тот же проект.
- Длина клипа округляется вверх до целого такта; `--length` задаёт её явно.
- Нотация: `c4/4 d e f g`, аккорд `(c4 e4 g4)/2`, пауза `r/8`,
  velocity `:V`, такт `|`, комментарий `#`.

### `analyze` — инспектор аудио

```text
euterpia analyze <файл.wav> [ключи]
```

- Отчёт с локализацией: клиппинг, DC offset, щелчки, провалы,
  «зависший» буфер, жужжание 50/60 Гц, признаки алиасинга, резкость.
- `--fail-on info|warn|error` — порог для CI (умолчание `error`).
- `--snippets <каталог>` пишет короткие WAV вокруг дефектов,
  `--heatmap <файл.pgm>` — спектрограмму, `--fft <N>` — размер кадра БПФ.
- Вердикт «нравится» остаётся за слушателем: инструмент указывает места
  и причины.

### `doctor` — самодиагностика окружения

```text
euterpia doctor
```

Секции: `build`, `audio`, `midi`, `plugins`, `fs`, `csrc`. Аудиоустройство
при этом **не открывается**. Код 0, если провалов нет; 2 — если есть.
Машинный вид: `euterpia doctor --json` (сводка `ok/warn/fail` совпадает с
кодом возврата).

### `config` — настройки окружения

```text
euterpia config <list|get|set|unset|path>
```

- Приоритет значения: argv > env (`EUTERPIA_*`) > файл > умолчание.
- Файл: `config path`; переопределение пути — `EUTERPIA_CONFIG`.
- Ключи: `backend`, `device`, `sampleRate`, `blockSize`, `grid`,
  `pluginPaths`, `cacheDir`, `recordDir`, `output`, `logLevel`.
- `get` печатает источник каждого значения: `argv`, `env`, `file`,
  `default` или `none`.
- Битый конфиг — предупреждение в stderr, команда работает на источнике ниже.

### `completion` / `help` / `version`

```text
euterpia completion <bash|zsh|fish>
euterpia help [команда]
euterpia version
```

- `completion` печатает скрипт; кандидаты берутся из реестра через
  служебную `__complete`, поэтому список команд в шаблонах отсутствует (#259).
- `help` без аргумента — общая справка; `help <команда>` — справка по
  команде; `--json` даёт машинный вид.
- `version` и `--version` печатают версию из того же модуля, из которого
  nimble берёт версию пакета (#88).

## Сценарии

Сценарии выполняются как написано (копипаст). Роль `euterpia` — собранный
`build/euterpia` или установленный в PATH.

### Создать проект, собрать граф и отрендерить (§19)

```bash
euterpia init song.eut --name "Demo" --tempo 100

euterpia node add oscillator --file song.eut --name osc
euterpia param set osc freq 220 --file song.eut
euterpia node add gain --file song.eut --name out
euterpia connect osc:out out:in --file song.eut
euterpia param set out level 0.5 --file song.eut

euterpia graph check --file song.eut          # компиляция через Core
euterpia render song.eut out.wav --seconds 3  # офлайн-рендер, без устройства
euterpia analyze out.wav --fail-on error      # инспектор для CI
```

Машинный вариант любого шага: добавить `--json`.

### Импортировать партитуру и отдать наружу

```bash
cat > motif.notes <<'EOF'
c4/4 d e f | g/2 r/2
EOF

euterpia notation check motif.notes
euterpia notation import motif.notes --file song.eut --track "Lead"
euterpia midi song.eut --out song.mid
```

### Проверить окружение перед живым запуском

```bash
euterpia doctor                 # человеку
euterpia doctor --json | jq .   # агенту: сводка, секции, факты
euterpia config get backend     # откуда взялось значение
```

## Согласованность документации и кода

Справочник обязан **не расходиться** с кодом (#96). Это обеспечивается
структурно, а не дисциплиной:

- `--help` и `help --json` строятся из одного реестра `cli/registry.nim`;
- `tests/cli_test.nim` проверяет, что каждая команда из `help --json`
  упомянута в этом справочнике, и что `--help` детерминирован;
- при добавлении команды её нужно внести в реестр (иначе её нет в CLI),
  а тест укажет, что её нет в `docs/cli.md`.

Со ссылками на открытые Issues (не выдаются за готовое):

- `transport`/`play`/сессия живого воспроизведения — ещё нет (#91, #92).
- Запись входа (#94), MIDI-мониторинг (#93), скан плагинов (#95).
- `param set` отвергает дробные значения из-за флагов-маски — план v0.3.2
  ([#292](https://github.com/framefrok/Euterpia_core/issues/292)).
- Батч/REPL (`--script`) — нет (#97).
- Формат WAV только PCM; реальные кодеки FLAC/OGG/MP3/AIFF — в плане (#10).
- Поставка (инсталлятор, ассоциации файлов, проверка на чистой машине) —
  [#229](https://github.com/framefrok/Euterpia_core/issues/229).

Полный план линии — README, раздел «План» и `docs/versions.md`.
