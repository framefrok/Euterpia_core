# План шага v0.3.3 — «Функциональность P1»

Шаг `.3` линии v0.3 (MANIFEST §105, `docs/versions.md` §2): **функции
приоритета P1**. Фундамент (control/query, handle-ID, сессии) закрыт в
v0.3.2, поэтому здесь — то, без чего ядро нельзя назвать DAW для
пользователя: клипы проекта в графе, живой звук, автосохранение и сдача.

Источники: milestone v0.3.3 и Issues #87, #92, #147, #209. Дублировать
Issues запрещено — документ только фиксирует объём, порядок и критерии.

## 1. #87 — плеер секвенсора

- `nodes/builtin/io/sequencer_player.nim`: нода `euterpia.sequencer`,
  `SequencerRuntime.processBlock`, sample-accurate `frameOffset` с поправкой
  на долю тика, `setCompiledSequencer` на control-path, `droppedEvents`.
- `scene_loader` компилирует `sequencerFromProject` для таких нод и
  отключает раскладку «дорожка → `euterpia.notes`» (иначе двойное звучание).
- Тесты: `test_sequencer_player`, `test_scene_ownership` (рендер проекта без
  нотных нод).
- Автоматизация в control-порты — отдельный шаг (в issue разрешён отдельный
  PR), потому что это уже связь секвенсора с control-слоем.

## 2. #92 — живое воспроизведение

- `cli/cmd_live.nim`: `device list` (бэкенды и устройства через реестр;
  пустой список — успех) и `play` (сцена → `AudioEngine` → `backend_manager`,
  метрики раз в секунду, NDJSON при `--json`, SIGINT/SIGTERM → stop/close,
  exit 0).
- Явно неверный индекс устройства — код 2; неизвестный бэкенд — код 1 с
  объяснением, что portaudio в этой сборке не залинкован (#52).
- Тесты: `cli_test` (устройства, отсутствие устройства/проекта, «nan»),
  `test_backend_registry` (hot-swap на фейковых адаптерах).

## 3. #147 — автосохранение

- `core/autosave.nim`: writer thread, очередь «последняя версия», атомарная
  запись, ротация, маркер `<проект>.autosave.lock`, `recoverAutosave`,
  `loadAutosave`.
- Политика — данными (`intervalMs`, `minChanges`, `keepSnapshots`,
  `maxSnapshotBytes`, `idleTimeoutMs`), решение проверяется отдельно
  (`shouldSnapshot`).
- Тесты: политика, устаревшая версия, «последняя побеждает», предел размера,
  ротация, восстановление после «аварии» (`graceful = false`), битый снимок,
  файл пользователя не перезаписывается.
- Политика CLI/Editor и связка с crash guard (#120) остаются в #110/#120:
  здесь — механика, на которую они опираются.

## 4. #209 — сдача материала

- `core/loudness.nim`: K-взвешивание BS.1770, интегрированная LUFS,
  short-term, LRA, true peak ×4 (windowed-sinc), нормализация и
  lookahead-лимитер; покадровое усиление (`gainEnvelope`) для стемов.
- `wav_codec`: TPDF-dither (детерминированный xorshift32) и RIFF `LIST/INFO`;
  32-битный PCM (`render --bits 32`) — промежуточный файл мастера.
- `cli/cmd_master.nim`: вход — проект или WAV; мастер + `--stems` +
  `--meta` + манифест с SHA-1; отчёт «что получилось» (LUFS до/после,
  true peak, усиление, лимитер, ошибка суммы стемов).
- Стемы рендерятся существующей командой `render --solo-track` и получают
  то же покадровое усиление, что мастер; поэтому их сумма сходится к мастеру
  (проверяется в `test_scene_ownership` и `test_loudness`).
- FLAC **читается**, но не пишется: энкодера в ядре нет (#10). `master`
  отвергает FLAC-выход с указанием причины — обещать «lossless» без
  кодировщика нельзя.
