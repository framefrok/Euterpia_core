# План шагов v0.3.6–v0.3.11 — «Полноценная линия CLI»

Линия `v0.3` — CLI. Шаги `.1`–`.2` дали инфраструктуру и каркас, `.3`–`.5` —
функции по приоритету (транспорт и живое воспроизведение, плагины, MIDI,
запись, кодеки, полировка). Функции есть, а **инструментария у CLI нет**:

- описание команды пишется трижды руками (диспетчер, `help`, `docs/cli.md`) и
  расходится;
- последовательность команд не является файлом: «создать, соединить, отрендерить»
  живёт в голове и в истории Bash;
- «что изменилось» между двумя проектами или рендерами нечем посмотреть, кроме
  как открыть два файла рядом;
- повторяемая практика (заготовка rock-проекта, сет-лист, «тёплый виолончельный»)
  не хранится данными;
- бинарь работает только у того, кто собрал репозиторий.

Пока линия `v0.4` (GUI) не начата, это окно ещё открыто. Шаги `.6`–`.11`
закрывают именно этот разрыв: они не про новые звуки и не про формат файла,
а про **воспроизводимость, проверяемость и поставку**.

Трекинг: issue [#352](https://github.com/framefrok/Euterpia_core/issues/352).

## Идея, вокруг которой выстроена линия

Две библиотеки-«якоря», остальное — их следствия.

### 1. `libs/script` — сценарий как файл (v0.3.7)

Сценарий — это **последовательность команд control-слоя**, сохранённая в файл.
Control-слой дал всё необходимое: команды сериализуются в JSON с версией
формата, транзакции атомарны, история знает обе стороны операции. Осталось дать
им файл.

```text
euterpia script record session.eproj script.eus      # записать, что делали
euterpia script run script.eus --file session.eproj  # повторить
euterpia script plan script.eus                    # показать, НЕ применяя
```

Что это даёт:

- **воспроизводимость**: пьеса = сценарий + проект, а не список команд в
  сообщении чата;
- **проверяемость**: сценарий исполняется в CI и даёт тот же документ побайтово;
  «звук не изменился» становится фактом, а не традицией (#148, golden-рендер);
- **данные вместо кода**: эталон для `diff` — это сценарий, шаблон — это
  сценарий, «быстрый старт» — это сценарий, который исполняется в CI.

### 2. `libs/cli_spec` — описание команды в одном месте (v0.3.6)

```text
CommandSpec: имя · синопсис · ключи (тип, умолчание, обязательность) · пример · схема --json
```

Из одного описания строятся human-справка, `--json`-схема, автодополнение оболочки
и раздел `docs/cli.md`. Сегодня эти четыре вещи пишутся руками, и тест #96
проверяет только *наличие* команды в справочнике — расхождение в описании ключей
или примера он не ловит, а человек получает справку, которая врёт.

Тот же шаг наводит порядок в расширении файла проекта: `.eproj` — основное,
`.eut` — историческое (расширение это подпись файла, а не формат, §19/§58), но
список расширений один на все команды (#370). Без этого «единый контракт»
неполон: правило «какой аргумент считается файлом проекта» жило копиями в
`cli/cmd_graph.nim` и `cli/cmd_render.nim` и уже расходилось.

## Порядок и зависимости

Порядок не перескакивает: сначала контракт и данные, потом надстройки.

| Шаг | Тема | Опорные issues | Зависит от |
|---|---|---|---|
| `v0.3.6` | Единый контракт: описание команд, чтение через Query API, `undo`/`redo`, коды ошибок | #330, #336, #331, #332, #370 | v0.3.2 (control-слой #139, handle-ID #143) |
| `v0.3.7` | Сценарии: `libs/script`, `--script`/REPL/NDJSON (#97), сценарий как тест | #333, #334, #335 | v0.3.6 |
| `v0.3.8` | Сравнение и проверки: `libs/diff`, `project diff`, `validate --strict`, `ci check` | #337–#340 | v0.3.7 (эталон — сценарий) |
| `v0.3.9` | Шаблоны и сет-листы: `libs/presets`, `init --preset`, пресеты параметров | #341–#343 | v0.3.7 (применение — транзакция) |
| `v0.3.10` | Итеративная работа: `libs/watch`, `--metrics`, интерактивный `analyze`, `doctor --deep` | #344–#347 | v0.3.6 (формат вывода) |
| `v0.3.11` | Поставка и полировка: сборки и ассоциации `.eproj` (#229), man-страницы, политика команд, быстрый старт | #348–#351 | v0.3.7 (сценарий быстрого старта) |

Почему такой порядок:

- **`v0.3.6` первым** — сценарий, описание команды и код ошибок ссылаются на
  один контракт; строить их раньше контракта значит переписывать;
- **сценарии раньше diff и шаблонов** — эталон для сравнения и применение
  шаблона сами являются сценариями;
- **поставка последней** — она проверяет всё построенное на настоящей машине, а
  не в репозитории.

## Что закрывает каждый шаг

- [x] `v0.3.6`: `docs/cli.md`, `help` и автодополнение собираются из одного
      описания; CLI не ходит во внутренности модели; `undo`/`redo` работают;
      каждая причина отказа даёт документированный код возврата.
- [x] `v0.3.7`: проект из MANIFEST §19 создаётся, правится и рендерится **одним
      сценарием**; `plan` не меняет ничего; сценарий исполняется в CI.
- [x] `v0.3.8`: изменение одной величины показывается как одно различие с
      адресом сущности; `ci check` падает с указанием шага.
- [x] `v0.3.9`: `init --preset` даёт проект, проходящий `graph check` без правок;
      применение шаблона — транзакция.
- [x] `v0.3.10`: цикл «правка → рендер» без ручного повторения; метрики видны
      во время рендера; вердикт инспектора одинаков в human, HTML и `--json`.
- [x] `v0.3.11`: бинарь с чистой машины проходит сценарий до звука; сценарий,
      написанный до переименования команды, продолжает работать.

## Заметки

- **Статус `v0.3.6`** (после #330, #336): контракт описания команд собран —
  `libs/cli_spec` даёт `--help`, `help --json`, автодополнение и раздел
  `docs/cli.md` из одного источника (#330), правило «какой аргумент — файл
  проекта» тоже живёт в одном месте (#370), а чтение идёт через Query API:
  `node list/show`, `param list/get/set` и `project show` не знают
  внутренностей модели, обход коллекций документа запрещён guard'ом (#336).
  Таблица «причина → код возврата» собирается данными (`cli/exit_codes.nim`,
  #332), публикуется в `help --json` и генерируется в `docs/cli.md`. `undo`/
  `redo`/`history` добавлены (#331): история лежит сайдкаром рядом с проектом
  (`<проект>.history`) и переживает перезапуск CLI — шаг `v0.3.6` закрыт.
- **Статус `v0.3.7`** (после #333, #334, #335): сценарий — это данные
  (`libs/script`, формат `euterpia.script` v1): команды control-слоя,
  переменные с сохранением типа, `run`/`plan`/`show`/`record`/`render`.
  `plan` принимает документ по значению и потому не может ничего записать;
  `run` идёт одной транзакцией и оставляет запись истории, поэтому `undo`
  отменяет сценарий целиком. Пакетный режим (`--script`), перенаправленный
  stdin и REPL — одна сессия и один разбор argv (`cli/dispatch`); в `--json`
  каждая команда даёт отдельную строку (NDJSON). Эталон рендера (#335) —
  метрики, SHA-1 файла, сценария и сэмплов; обновляется только командой
  `--update-baseline`, проверяется в CI (`tools/script_scenario.sh`). Шаг
  `v0.3.7` закрыт.
- **Статус `v0.3.8`** (после #337–#340): сравнение стало данными
  (`libs/diff`). `project diff a b` сопоставляет сущности по `id`, поэтому
  перестановка ключей и порядка нод различием не считается, а изменение
  одной величины даёт ровно одно различие с адресом (`node:1.parameters.freq`,
  `track:1/clip:7/note:0:60:0.velocity`, `connection:1.a0->2.a0`). `render diff`
  объясняет расхождение звука числом: метрики (пик, RMS, DC, спектральный
  центроид, доли трёх полос) и поштучное сравнение сэмплов с кадром первого
  расхождения. `--exit-code` превращает различия в код 1 — гейт для CI.
  `project validate --strict` добавляет пять lint-секций (висячие ссылки, дубли,
  диапазоны, неиспользуемое, типы нод) и третий уровень `note` («на заметку»:
  код возврата меняет только `fail`); циклы не дублируются — их находит
  компилятор в `graph check`. `ci check` — один вход для CI:
  validate → graph → render → analyze, код возврата упавшего шага, вывод шагов
  сохраняется в отчёте и при провале, `--strict` включает lint и порог `warn`,
  `--fast` оставляет только validate и graph. Шаг `v0.3.8` закрыт.
- **Статус `v0.3.9`** (после #341–#343): заготовки стали данными
  (`libs/presets`, форматы `euterpia.preset`, `euterpia.setlist`,
  `euterpia.param-preset` v1). Шаблон проверяется реестром нод ДО применения
  (неизвестный тип — `not_found`), `init --preset band` собирает проект тем же
  путём, что `script build`, и он проходит `graph check` без правок.
  `preset apply` к существующему проекту — одна транзакция (отказ не оставляет
  следов, `undo` отменяет целиком). Сет-лист собирает пьесу поверх шаблона и
  обновляет существующую дорожку `clip.set`, а не плодит клипы; сведение —
  параметры голоса. Пресет параметров применяется по типу и роли, отчёт
  называет изменённое, совпавшее и не попавшее под роль. Шаг `v0.3.9` закрыт.
- **Статус `v0.3.10`** (после #344–#347): цикл «правка → рендер» стал
  командой (`watch`, `libs/watch`): дебаунс, ограничение частоты, атомарный
  вывод и корректный Ctrl-C проверяются без сна и мигания. Поток метрик
  (`--metrics`, `--metrics-interval`, `--metrics-event`) идёт NDJSON в stdout
  при `--json` и короткой строкой в stderr в human; в офлайн-рендере `t` —
  время аудио, поэтому поток детерминирован. `analyze` печатает вердикт,
  гистограмму и спектр в терминале (ASCII без TTY, цвет при TTY), пишет
  самодостаточный HTML и отдаёт тот же вердикт в `--json`. `doctor --deep`
  проверяет проект (загрузка, граф, lint, файлы ресурсов), время каждой
  проверки видно в отчёте (`elapsedMs`), а быстрый `doctor` не изменился.
  Шаг `v0.3.10` закрыт.
- **`v0.3.11` status** (after #348–#351): the CLI line is closed. Delivery
  provides `euterpia open` and the `euterpia-open` helper (a file association
  opens the project in its own directory); man pages and completion for four
  shells are generated from the specification and verified by `__man --check`;
  the compatibility policy is executable (aliases, deprecation,
  `validateSpecs`); the documented quick start runs in CI and on a clean
  machine. Tracking issue #352 is closed with the milestone.
- **`script build`** (v0.3.8, #416): пересборка проекта из сценария «с нуля».
  Это примитив, на который опирается `v0.3.9`: `init --preset` — тот же
  `build`, где пресет поставляет сценарий и метаданные, а не второй путь
  сборки. Перезапись требует `--force`, прежний проект остаётся в `.bak`,
  история — в `.history.bak` (документ заменён целиком, поэтому стек отмены
  начинается заново). Потери, которые сценарий пока не выражает (ресурсы,
  состояния плагинов, автоматизация), не происходят молча: отказ или
  `--allow-loss`. Тем же правилом исправлен `init --force`.
- **Даты milestone'ов v0.4** (с 2027-02-02) после этой линии требуют
  переноса: шесть шагов занимают примерно полгода. Перенос — решение владельца
  линии, здесь не делался.
- **#97** (`--script`, REPL) перенесён из `v0.3.5` в `v0.3.7`: батч и REPL —
  это сценарии, а не полировка.
- Линия не трогает realtime: всё — control-path и build-time.
