# tests/scenarios — сценарий как тест (#333, #335)

Здесь лежит эталонный прогон: **сценарий, базовый проект и эталон рендера**.
Он исполняется в CI (`tools/script_scenario.sh`, шаг `nimble cliSmoke`).

| файл | что это |
|---|---|
| `golden.eus` | сценарий: две ноды, связь и два параметра (переменные `freq`, `gain`) |
| `golden.base.eproj` | базовый документ: пустой проект. Сценарий применяется **в памяти**, файл не меняется |
| `golden.baseline.json` | эталон: метрики, SHA-1 файла, текста сценария и сэмплов |

## Зачем это тест, а не пример

Эталон не «помнят руками»: он собирается из сценария тем же офлайн-рендером,
что и обычный `render`. Правка графа, DSP или формата проекта, меняющая звук,
роняет сверку — CI видит это как код 1 и список различий.

## Как обновить эталон

Обновление — **отдельная явная команда**, а не побочный эффект прогона:

```bash
build/euterpia script render tests/scenarios/golden.eus \
  --file tests/scenarios/golden.base.eproj \
  --out /tmp/golden.wav --seconds 1 \
  --baseline tests/scenarios/golden.baseline.json --update-baseline
```

Команда печатает, что изменилось относительно прежнего эталона (кадры,
частота, пик, RMS, SHA-1 сценария), поэтому обновление видно в diff, а не
происходит молча. `--dry-run` не пишет и эталон.

## Почему базовый проект пустой

Сценарий описывает правку, а не состояние: `node.create` на уже собранном
графе честно откажет (`already exists`). Поэтому база — пустой проект, а
`golden.base.eproj` не меняется ни одним прогоном.
